# 模拟数值上限设计

## 1. 概述

本文档描述 Biod 模拟系统中所有数值上限的定义、检查机制和操作行为，作为后续开发和修改的唯一权威参考。

---

## 2. 上限定义

### 2.1 三层上限体系

| 层级 | 常量/字段 | 定义位置 | 默认值 | 说明 |
|---|---|---|---|---|
| L1 群体数量上限 | `MAX_FLOCKS` | [Simulation.h:21](file:///d:/HuChao_Dev/Projects/Biod/src/simulation/Simulation.h#L21) | 12 | 用户可创建的最大群体个数 |
| L2 全局个体上限 | `Simulation::m_maxBoids` | [GLWidget.cpp:16](file:///d:/HuChao_Dev/Projects/Biod/src/ui/GLWidget.cpp#L16) | 10000 | 所有群体 boid 总数上限 |
| L3 单群个体上限 | `FlockParams::maxFlockSize` | [FlockData.h:77](file:///d:/HuChao_Dev/Projects/Biod/src/simulation/FlockData.h#L77) | 2000 | 单个群体 boid 数量上限 |

### 2.2 层级关系

```
L1 (MAX_FLOCKS)  >=  当前群体个数
L2 (m_maxBoids)  >=  SUM(所有群体 boid 数)
L3 (maxFlockSize) >=  单个群体 boid 数 (对每个群体独立约束)
```

**L2 与 L3 的关系**：`m_maxBoids` (10000) 独立于 `maxFlockSize × MAX_FLOCKS` (24000)。理论上 12 群 × 2000 = 24000 远超 10000，但两者是独立上限，以更严格者为准。

## 3. 各操作路径的检查逻辑

### 3.1 用户手动生成 (spawnRandom)

**触发**：用户点击 "Spawn" 按钮 → [MainWindow.cpp:798](file:///d:/HuChao_Dev/Projects/Biod/src/ui/MainWindow.cpp#L798)

**代码位置**：[Simulation.cpp:777](file:///d:/HuChao_Dev/Projects/Biod/src/simulation/Simulation.cpp#L777)

**检查顺序**：

```
1. per-flock caps: countInFlock(activeFlock) + requested >= maxFlockSize
   → YES: 缩减 count 到可用空间或直接 return
   
2. global cap:   m_data.count + count > m_maxBoids
   → YES: 缩减 count = m_maxBoids - m_data.count

3. count <= 0
   → return (无可生成)
```

**失败行为**：静默缩减数量或返回，**无 UI 提示**

**已知偏差**：全局与单群的检查顺序与直觉相反（应先全局后单群）

### 3.2 用户单次添加 (addBoid)

**触发**：程序内调用，目前无直接 UI 入口

**代码位置**：[Simulation.cpp:763](file:///d:/HuChao_Dev/Projects/Biod/src/simulation/Simulation.cpp#L763)

**检查顺序**：

```
1. global cap:   m_data.count >= m_maxBoids
   → return
   
2. per-flock cap: countInFlock(activeFlock) >= maxFlockSize
   → return
```

**失败行为**：静默返回，**无 UI 提示**

**已知偏差**：检查顺序与 `spawnRandom` 不一致（此函数先全局后单群）

### 3.3 自动繁殖 (updateReproduction)

**触发**：每个繁殖间隔自动调用 → Simulation::update() 每帧末尾

**代码位置**：[Simulation.cpp:615](file:///d:/HuChao_Dev/Projects/Biod/src/simulation/Simulation.cpp#L615)

**检查顺序**（11 层防护）：

| # | 位置 | 检查 | 类型 |
|---|---|---|---|
| G1 | L617 | `m_data.count >= m_maxBoids` → return | 全局入口 |
| G2 | L625 | `simTime - lastTime < interval` → continue | 时间间隔 |
| G3 | L640 | `flockSize >= maxFlockSize` → continue | 单群硬上限 |
| G4 | L642-646 | `capScale` 线性缩减 (90% 软上限) | 单群软上限 |
| G5 | L648-649 | `m_maxBoids - m_data.count <= 0` → return | 全局检查 |
| G6 | L668 | `maxNew = min(globalRoom, pairs*maxOffspring)` | 新生上限 |
| G7 | L669 | `maxNew = min(maxNew, maxFlockSize - flockSize)` | 单群空间 |
| G8 | L670 | `maxNew *= capScale` | 软上限衰减 |
| G9 | L671 | `maxNew <= 0` → continue | 跳过 |
| G10 | L673 | `spawned < maxNew` 循环守卫 | 循环边界 |
| G11 | L676 | `babies = min(babies, maxNew - spawned)` | 内层边界 |

**结论**：繁殖路径的容量检查**最完整**，无遗漏。G5 已修正为 `continue`（保持所有群体平等繁殖机会）。

### 3.4 增加/删除群体 (addFlock / removeFlock)

#### addFlock

**代码位置**：[Simulation.cpp:693](file:///d:/HuChao_Dev/Projects/Biod/src/simulation/Simulation.cpp#L693)

**检查**：

```
1. flock count:   n >= MAX_FLOCKS
   → return -1
```

**未检查项**：
- 不检查 L2（全局 boid 总量）——理论上可以在 boid 已满时仍创建空群体

## 6. 建议修正方案（供后续开发参考）

### 6.1 统一检查顺序

所有添加路径统一为：**全局上限 → 单群上限**

```
addBoid / spawnRandom:
  1. m_data.count >= m_maxBoids → notify + return
  2. countInFlock(fid) >= maxFlockSize → notify + return
  3. 执行添加
```

### 6.2 补齐 UI 反馈

- 所有返回 `false`/`-1`/`<=0` 的操作路径，在 UI 层通过 `QStatusBar` 或 `QMessageBox` 提示用户
- 提示信息应包含：当前值、上限值、操作被拒原因

### 6.3 统一返回值类型

- `addFlock()` 改为返回 `bool`，或在调用方正确检查 `>= 0`

### 6.4 可选增强

- `addFlock` 增加全局容量预检查（如果 boid 已满则不允许创建空群体）
- `spawnRandom` 失败时通过返回值告知调用方实际生成了多少 boid
